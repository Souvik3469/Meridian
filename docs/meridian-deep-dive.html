Meridian — Architecture Deep Dive

1. Overview

Meridian is a pre-trip planner for US property-carrying truck drivers. The driver enters a current location, an ordered list of stops (pickup or dropoff), and the on-duty hours already used in the current 70-hour/8-day cycle. The system returns a truck route on a map, the rest and fuel stops the law or the product requires, and one filled FMCSA daily log sheet per day.

HOS (Hours of Service) is the set of FMCSA (Federal Motor Carrier Safety Administration) rules that cap how long a commercial driver may drive and stay on duty.

AspectValue
BackendDjango 6.0.6 + Django REST Framework 3.17.1, one app: trips
HOS rulesbackend/trips/hos/engine.py — pure Python, no I/O, no Django imports
External APIOpenRouteService (ORS): geocoding, autocomplete, truck (HGV) routing
FrontendReact 19 + Vite 8, Leaflet via react-leaflet 5, SVG log sheets
PersistenceNone for product data. SQLite exists only for Django's built-in apps
HostingBackend on Render (render.yaml, Gunicorn). Frontend on Vercel (static build)
Tests44 backend tests in 5 modules under backend/trips/tests/, all passing

Scope. Property-carrying driver. 70-hour/8-day cycle. 11-hour driving limit, 14-hour duty window, 30-minute break after 8 hours of driving, 10-hour daily reset, 34-hour cycle restart. Product assumptions: fuel every 1,000 miles (30 min), 1 hour on duty at each stop plus any user-entered delay.

Out of scope (documented in the engine docstring and README). Sleeper-berth split, adverse-driving exception, short-haul exception, calendar-anchored dates.

3.2 Flow A — Plan a trip

  1. TripForm.jsx → handleSubmit builds the payload with buildPayload and calls the onSubmit prop.
  2. App.jsx → handleSubmit sets loading state, clears old result, calls planTrip.
  3. api/tripService.js → POST {API_BASE_URL}/api/trips/plan/ with JSON body.
  4. config/urls.py → routes api/ to trips/urls.py.
  5. trips/urls.py → trips/plan/ resolves to PlanTripView.
  6. DRF throttle (settings.py REST_FRAMEWORK) → ScopedRateThrottle checks scope trip_plan; 429 if exceeded.
  7. views.py PlanTripView.post → validates with serializers.py, calls plan_trip.
  8. planner.py → geocodes every location via services/geocoding.py.
  9. services/routing.py → one ORS directions call for all waypoints; returns legs + geometry.
  10. hos/engine.py → build_duty_schedule produces the flat timeline; split_into_days slices it per 24 h.
  11. services/geometry.py → point_at_distance places rest/fuel pins on the route polyline.
  12. planner.py → returns {route, days, summary}; views.py wraps it in Response (200).
  13. App.jsx → stores result, tripInputs, sets hasPlannedOnce; renders StatTiles, MapView, LogSheetList.

3.3 Flow B — Location autocomplete

  1. LocationAutocomplete.jsx → useEffect on value; skips if under 3 chars; debounces 300 ms.
  2. api/locationService.js → GET /api/locations/autocomplete/?q=... with an AbortController signal.
  3. trips/urls.py → LocationAutocompleteView (throttle scope location_autocomplete).
  4. views.py LocationAutocompleteView.get → strips q; returns {results: []} if under 3 chars.
  5. services/geocoding.py autocomplete → ORS /geocode/autocomplete, maps features to {label, lat, lng}.
  6. views.py → on GeocodingError returns {results: []} with 200 (soft fail).
  7. LocationAutocomplete.jsx → drops the response if requestIdRef moved on; opens the list only if the field is still focused.

3.4 Flow C — Replan with a stop delay

  1. TripForm.jsx → user edits the Delay (hrs) field of a stop; setStopField updates stops.
  2. TripForm.jsx → submit button reads "Replan trip" (hasResult prop); buildPayload sends extra_delay_hours as a number.
  3. Same path as Flow A from step 2. There is no partial-update endpoint.
  4. planner.py → converts each stop to on-duty hours PICKUP_DROPOFF_HOURS + extra_delay_hours.
  5. hos/engine.py → full re-simulation; a longer stop can push a later drive past a limit and add a new rest.

3.5 Flow D — Print / export

  1. App.jsx → "Print / Save as PDF" button calls window.print().
  2. App.css @media print → hides .no-print, shows .print-only.
  3. LogSheetList.jsx → print-only trip line (current → stop1 → stop2) plus one LogSheet per page.

4.4 State machine — what drive() does each loop iteration

                 +---------------------------------------------+
                 | compute headroom:                           |
                 |  window_left, driving_left, break_left,     |
                 |  cycle_left, fuel_left (hours at leg speed) |
                 +----------------------+----------------------+
                                        |
                  chunk = min(remaining, all headrooms)
                                        |
                 +----------------------+----------------------+
                 | chunk > EPS                                 | chunk <= EPS
                 v                                             v
        append DRIVING(chunk)                 first binding limit, in priority order:
        remaining -= chunk                      break_left<=EPS      -> _take_break()        (0.5h ON_DUTY)
        miles += chunk*speed                    window/driving<=EPS  -> _take_daily_reset()  (10h OFF)
                 |                              cycle_left<=EPS      -> _take_restart()      (34h OFF)
                 |                              else (fuel)          -> _take_fuel_stop()    (0.5h ON_DUTY)
                 |                                             |
                 +-------------------> loop while remaining > EPS <---+

on_duty() uses the same pattern with only two limits: window_left → _take_daily_reset(), cycle_left → _take_restart().

Duty-status transitions that can appear in output:

  OFF_DUTY ("Before trip start")  --> DRIVING
  DRIVING --> ON_DUTY_NOT_DRIVING  (30-minute break / Fuel stop / Pickup at X / Dropoff at X)
  DRIVING --> OFF_DUTY             (10-hour rest period / 34-hour restart)
  ON_DUTY_NOT_DRIVING --> DRIVING
  ON_DUTY_NOT_DRIVING --> OFF_DUTY (window or cycle exhausted during a stop)
  OFF_DUTY --> DRIVING or ON_DUTY_NOT_DRIVING
  SLEEPER_BERTH: declared, never emitted

5. LLD — Function-wise Flow

5.1 Plan a trip

handleSubmit(event) in TripForm.jsx

  • Calls event.preventDefault(), then onSubmit(buildPayload(values, stops)).

buildPayload(formValues, formStops) in TripForm.jsx

  • Input: string form state.
  • Output: current_cycle_used_hours as Number, each extra_delay_hours as Number(...) || 0, trip_start_time as the HH:MM string or null.

handleSubmit(payload) in App.jsx

  • Side effects: isSubmitting=true, error=null, result=null.
  • On success: result, tripInputs, hasPlannedOnce=true. On throw: error=err.message. finally: isSubmitting=false.

planTrip(payload) in api/tripService.js

  • fetch POST with JSON; parses JSON body.
  • If !response.ok: throws Error(data.detail || Object.values(data).flat().join(' ')).

PlanTripView.post(request) in views.py

  • TripRequestSerializer(data=request.data).is_valid(raise_exception=True) → DRF returns 400 with field errors on failure.
  • Calls plan_trip(**serializer.validated_data).
  • Catches GeocodingError → 400 {"detail": str(exc)}; RoutingError → 502 {"detail": str(exc)}.

plan_trip(current_location, stops, current_cycle_used_hours, trip_start_time=None) in planner.py

  1. geocode(current_location), then geocode(stop["location"]) for each stop, sequentially. N stops → N+1 ORS calls.
  2. get_route([current_coords, *stop_coords]) → one ORS call.
  3. trip_start_hour = hour + minute/60 or 0.0.
  4. Builds one RouteLeg(leg.distance_miles, leg.duration_hours, "En route to <location>") per zip(route.legs, stops).
  5. Stop labels: "<Type> at <location>", e.g. "Pickup at Colorado Springs, CO".
  6. On-duty hours per stop: PICKUP_DROPOFF_HOURS + stop.get("extra_delay_hours", 0.0).
  7. build_duty_schedule(...) → entries.
  8. stops_for_map: current, then each stop, then one pin per entry whose label is in STOP_TYPES_BY_LABEL, located by point_at_distance(route.geometry, entry.distance_marker_miles).
  9. split_into_days(entries) → days.
  10. summary.total_trip_hours = entries[-1].end_hour; requires_34_hour_restart = any(label == "34-hour restart").
  11. No DB writes. Errors from steps 1–2 propagate.

geocode(location_text) in services/geocoding.py

  • GET ORS_GEOCODE_URL with api_key, text, size=1, timeout 10 s; raise_for_status().
  • requests.RequestException → GeocodingError("Could not geocode '<text>': <exc>").
  • Empty features → GeocodingError("No location found for '<text>'").
  • Returns (lat, lng) from features[0].geometry.coordinates (ORS order is [lng, lat]).

get_route(waypoints) in services/routing.py

  • POST ORS_DIRECTIONS_URL (driving-hgv, HGV = heavy goods vehicle profile) with [[lng, lat], ...], timeout 15 s.
  • Network error → RoutingError. Non-200 → RoutingError("Routing request failed: <code> <body>"). Missing features/summary/segments/geometry → RoutingError("Unexpected routing response format").
  • Converts meters → miles (/1609.344), seconds → hours (/3600). One RouteLegResult per ORS segment.

build_duty_schedule(current_cycle_used_hours, legs, stop_labels, trip_start_hour=0.0, on_duty_hours=None) in hos/engine.py

  • Validates len(legs) == len(stop_labels) and len(on_duty_hours) == len(legs); else ValueError.
  • Defaults on_duty_hours to [1.0] * len(legs).
  • HOSEngine(current_cycle_used_hours, trip_start_hour); for each leg: engine.drive(...), then engine.on_duty(stop_hours, stop_label).
  • Returns engine.entries.

HOSEngine.__init__(current_cycle_used_hours, trip_start_hour=0.0)

  • Zeroes counters; seeds cycle_hours_used.
  • If trip_start_hour > _EPSILON: appends an OFF_DUTY block "Before trip start" from 0 to the start hour.

HOSEngine.drive(distance_miles, duration_hours, label)

  • Returns immediately if distance or duration ≤ ε.
  • avg_speed_mph = distance / duration (constant for the leg).
  • Loop (section 4.4): compute five headrooms, drive min(...), or insert the highest-priority rest.
  • Each driving chunk adds chunk * avg_speed_mph to miles_since_fuel and distance_traveled_miles.

HOSEngine.on_duty(duration_hours, label)

  • Loop bounded by window_left and cycle_left. Splits a long stop around a 10-hour reset or 34-hour restart if a limit is reached mid-stop.

HOSEngine._append(status, duration, label)

  • Ignores durations ≤ ε. Records LogEntry(status, clock, clock+duration, label, distance_traveled_miles); advances clock.
  • DRIVING: +duration to driving_hours_today, hours_since_break, cycle_hours_used.
  • ON_DUTY_NOT_DRIVING: +duration to cycle_hours_used; resets hours_since_break if ≥ 0.5 h.
  • OFF_DUTY/SLEEPER_BERTH: ≥ 0.5 h resets break; ≥ 10 h resets driving_hours_today and duty_window_start; ≥ 34 h resets cycle_hours_used.

split_into_days(entries) in hos/engine.py

  • For each entry, walks a cursor; day_index = int(cursor // 24); cuts at (day_index+1)*24.
  • Emits DayEntry with hours rebased to 0–24.
  • Per day: totals initialised with every DutyStatus value at 0.0, then summed.

point_at_distance(geometry, target_distance_miles) in services/geometry.py

  • target ≤ 0 or one point → first point. Walks segments summing haversine_miles; linearly interpolates lat/lng inside the containing segment; past the end → last point.

5.2 Autocomplete

useEffect([value]) in LocationAutocomplete.jsx

  • If skipNextLookupRef is set (just selected a suggestion): clear flag, return.
  • If value.trim().length < 3: clear suggestions, close, stop spinner.
  • Else: requestId = ++requestIdRef.current, spinner on, 300 ms timer → getLocationSuggestions(value, controller.signal).
  • Result is applied only if requestIdRef.current === requestId. isOpen = isFocusedRef.current && results.length > 0.
  • Cleanup on next keystroke: clearTimeout, controller.abort().

getLocationSuggestions(query, signal) in api/locationService.js

  • Returns [] on non-OK; else data.results || [].

LocationAutocompleteView.get(request) in views.py

  • q stripped; < MIN_AUTOCOMPLETE_QUERY_LENGTH (3) → {results: []}.
  • autocomplete(query_text); GeocodingError → results = []. Always 200.

autocomplete(query_text, limit=5) in services/geocoding.py

  • GET ORS_AUTOCOMPLETE_URL; maps each feature to {label: properties.label, lat: coords[1], lng: coords[0]}.

handleSelect(suggestion) in LocationAutocomplete.jsx

  • Sets skipNextLookupRef = true, calls onChange(name, suggestion.label), clears and closes the list.

5.3 Render results

StatTiles({route, dayCount, summary}) → formats distance_miles, duration_hours, formatTripDuration(summary.total_trip_hours) (switches to Nd Xh at ≥ 24 h), day count.

MapView({route}) → returns null if no geometry; centres on the middle geometry point; one Marker per route.stops item with a divIcon class dot--<type>; link from buildGoogleMapsDirectionsUrl(route.stops).

buildGoogleMapsDirectionsUrl(stops) in utils/googleMapsLink.js → filters to current/pickup/dropoff; returns null if fewer than 2; builds api=1&origin&destination&waypoints&travelmode=driving.

LogSheet({day}) → SVG, HOUR_WIDTH=30, ROW_HEIGHT=36, four rows from ROWS; DutyStepLine draws a horizontal segment per entry at rowY(status) and a vertical connector from the previous entry's row.

9. Design Decisions and Tradeoffs

DecisionWhyCost
Pure HOS engine (no I/O, no Django)Unit-testable with synthetic legs; deterministicCaller must translate real-world inputs (dates, prior duty) into engine terms
Headroom-min loop instead of per-rule branchesNew rule = one more term in min plus one priority branchPriority order is a judgement call and must be documented
One _append() updates all countersRest helpers cannot forget a counter_append grows with every new status rule
Stateless API, recompute on every replanNo stale plans; a delay cascades correctlyEvery replan re-pays all ORS calls
Single provider (ORS) for geocode, autocomplete, routingOne key, one quota, HGV profile availableSingle point of failure; no fallback
Geocode 400 vs routing 502Separates bad user input from upstream failure—
Autocomplete soft-fails to [] with 200Suggestions are optional; no error banner while typingSilent when ORS is down
Stops as a generic ordered listMulti-stop support with no engine change; type only affects map styling—
Frontend has no HOS logicOne source of truth for rulesEvery change needs a server round-trip
SVG log sheets at fixed size + horizontal scrollLegible on phones; prints one sheet per landscape pageHorizontal scroll on narrow screens
